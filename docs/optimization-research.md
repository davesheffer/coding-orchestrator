# Orchestration optimization audit — 2026-09-23

This audit covers the Codex and Claude Code paths in this repository. It separates measured behavior from model-price estimates and changes that still need live validation. The target is completed, correct work per unit of time and cost, with the existing permission boundaries preserved.

## What changed now

- New Codex installations start the coordinator on GPT-6 Sol/medium. Scout and runner start on GPT-6 Luna/low; builder uses GPT-6 Sol/medium; critic remains GPT-6 Astra/high. The Windows launcher's only model-unavailable fallback for Luna is Sol. Existing user `config.toml` files remain preserved by the installer, so this is a new-install default, not a forced migration.
- The bundled instructions no longer delay delegation until a 100k-token context threshold. They reserve the Astra critic for high-risk or unresolved low-confidence claims.
- Launcher reports now record preflight and model-attempt durations. The Windows bundle test explicitly decodes UTF-8 instructions.
- A local report command aggregates status, observed models, timing, and token use without printing task text. A constrained `--trial-model` option allows paired scout comparisons under the same launcher permissions.
- The initial Claude pilot routed bounded scout work to Haiku and specified edits to Sonnet. A later user preference maps Codex Sol to Opus 5.5, Luna/Tera to Sonnet, and Astra to Fable: the Claude coordinator now defaults to Opus 5.5 on installations without an explicit model choice, scout/runner/builder use Sonnet, and critic uses Fable. Role descriptions remain shorter, and the Claude instructions no longer wait for a 100k-token relay reading before useful delegation.
- Native Codex role files now explicitly disable the prohibited feature set. The launcher preserves existing MCP transport fields while disabling each discovered server, matching a previously installed local hardening change.
- The Claude installer applied the new role files and managed instructions to the local `~/.claude` home with backups. Its role validator passed. A selective local Codex sync updated the launcher, routine roles, and managed instruction block with backups while preserving the customized critic and both user-owned preference blocks.

OpenAI's current model guide places Luna on scoped tasks, Sol on everyday coding and work requiring judgment, and Astra on demanding analysis. It recommends comparing candidates on the same inputs and choosing the lightest setting that meets the quality bar: [model selection](https://developers.openai.com/api/docs/guides/model-selection). The [Codex subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) says parallel agents add tokens, child settings can inherit live parent permission overrides, and independent tasks are the best fit for delegation. These support bounded delegation and enforced launcher probes, but do not establish the best number of agents for this repository.

At the published **API Standard short-context** rates, GPT-6 Sol is one-fifth of Astra's input and output price per token; Luna is one-twentieth of Sol's. Cache-write and cached-input rates have their own accounting: [OpenAI pricing](https://developers.openai.com/api/docs/pricing). These are price ratios, **not** a measured saving for Codex subscriptions or completed coding tasks. Stronger models can finish in fewer turns; per-task cost and correctness must be measured.

Anthropic's [Claude Code cost guide](https://code.claude.com/docs/en/costs) recommends Sonnet for most coding, cheaper agents for simple work, small teams, narrow prompts, and summaries for verbose tests. Its [model optimization analysis](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence) shows why token price alone can reverse the ranking on cost per solved task. The local pilot measured Haiku and Sonnet scouts and a Sonnet builder, but did not compare Opus 5.5 against Fable for the main session. The user-selected route prioritizes the requested cross-client mapping over the small pilot's Haiku cost result. Claude's [feature guide](https://code.claude.com/docs/en/features-overview) also recommends keeping always-loaded instructions concise and moving occasional workflows to on-demand skills. The checked-in `CLAUDE.md` remains below that guide's 200-line rule of thumb.

## Highest-value next experiments

1. **Build a representative task set before another model change.** Capture at least 20 real tasks across lookup, exact checks, specified edits, ambiguous debugging, and risky review. Freeze the task brief and repository revision. Compare old and new routes on task completion, defect rate, elapsed time, model calls, input/output/cached tokens, fallback frequency, and human corrections. Use a second reviewer for correctness, blind to the model route. Do not infer quality from CLI exit zero. OpenAI recommends [traces and repeatable datasets](https://developers.openai.com/api/docs/guides/agent-evals) for this class of decision.
2. **Accumulate launcher timing.** `bin/agent-report.py` now aggregates `preflight_ms`, attempt duration, status, observed model, and tokens. The local pilot's preflight median is about 0.8 s; keep collecting by host and role before reducing checks. Fresh filesystem and network probes remain mandatory; caching an isolation verdict across runs would weaken the boundary.
3. **Test the delegation break-even point.** The six paired scout questions compare Luna and Sol *inside* the launcher, but do not compare direct main-session work against delegated work. Include briefing and verification time on real small and medium tasks. Delegate when it saves main-context growth or wall time without raising correction rate; keep tiny known-file operations local. Parallelize only independent branches, and cap concurrency based on measured throughput and token use. OpenAI's [latency guidance](https://developers.openai.com/api/docs/guides/latency-optimization) supports reducing output, avoiding unnecessary serial requests, and parallelizing independent work.
4. **Expand Claude route comparisons.** The local pilot covers six lookups and two edits under the prior route. Test runner commands, larger builds, and demanding main-session tasks on frozen real work to measure the new Opus 5.5/Sonnet/Fable route. Check the actual model in `/tasks`; [Claude subagent model resolution](https://code.claude.com/docs/en/sub-agents) allows per-invocation choices to override a role's model.
5. **Measure context reductions.** Role descriptions were shortened while permission and reporting instructions stayed intact. Compare model-visible prompt size and task behavior before trimming safety instructions. Stable prefixes can improve [prompt-cache reuse](https://developers.openai.com/api/docs/guides/prompt-caching); the CLI controls its own request construction, so API cache knobs should not be assumed available here.
6. **Finish native acceptance checks.** A fresh Codex config loaded through `codex debug prompt-input`, and the earlier Claude role validator and four role selections passed under the prior route. Recheck Claude on version 2.1.280 or later for Opus 5.5 and the new Sonnet scout. Codex Luna/Sol scouts and a Sol builder ran through probed restrictions; installed local roles parse with all 12 prohibited features disabled. `docs/client-validation.md` still needs Codex native child-role discovery, upgrade, full role/model-access, and compaction checks. On Windows, record the active sandbox and firewall profile; never treat a network-available fallback as isolation.

## Decision rule

Keep a cheaper route only when it meets the same correctness and permission criteria on the frozen task set. Rank candidates by **cost per correctly completed task** and median/p95 elapsed time, not token price or one successful demo. A model or prompt change should ship with the task-set result, native-client evidence where applicable, and a rollback path. The current change is a routing baseline aligned with local preferences; its end-to-end quality and monetary savings remain unverified.
